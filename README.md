# Real-Time Sign Language Alphabet Recognizer
#### Description:

This project is a real-time hand sign recognition system built with Python, OpenCV, and MediaPipe. It uses a laptop webcam to track the 21 landmark points of a human hand and feeds those landmarks into a simple machine learning model that predicts which letter of the alphabet the hand shape represents. The project is split into two files: `project.py`, which handles webcam capture, hand landmark detection, data collection, and live prediction, and `train_model.py`, which trains a K-Nearest Neighbors classifier on the collected data and saves it to disk. Together, these two files form a complete pipeline: collect training examples of hand signs, train a model on them, and then use that model to recognize signs in real time.

The core idea behind the project came from wanting to explore computer vision and machine learning together in a way that produces an immediately visible, interactive result rather than just a static accuracy score. MediaPipe's hand-tracking solution was chosen because it provides accurate, real-time 21-point hand landmark detection out of the box, without requiring a custom-trained detection model. This let the project focus on the more interesting problem of turning raw landmark coordinates into a usable classification system.

**How `project.py` works:** The script opens the default webcam and continuously reads frames in a loop. Each frame is converted from BGR to RGB, since MediaPipe expects RGB input, and passed to the MediaPipe Hands solution to detect a hand and its landmarks. If a hand is found, its landmarks are drawn onto the frame for visual feedback, and then the landmark coordinates are normalized. Normalization is one of the more important design decisions in the project: raw landmark coordinates are given as fractions of the frame width and height, which means the same hand shape produces very different numbers depending on how close the hand is to the camera or where it sits in the frame. To fix this, the wrist landmark (index 0) is treated as the origin, and every other landmark's x and y coordinates are calculated relative to the wrist. The result is then divided by the distance between the wrist and the base of the middle finger (landmark 9), which acts as a rough measure of hand size in the current frame. This scales the landmarks so that a hand held close to the camera and the same hand held farther away produce nearly identical normalized coordinates, making the resulting feature vector far more consistent for both training and prediction than raw pixel-fraction coordinates would be.

Once normalized, the 21 (x, y) pairs are flattened into a single list of 42 numbers. This flattened list serves two purposes depending on what key is pressed. If the person presses any single alphabetic key on the keyboard, the current frame's landmarks are labeled with that letter and appended as a new row to `data.csv`, building up a labeled dataset of hand shapes over time. This design lets a user "teach" the system their own hand signs simply by holding a shape and tapping the corresponding letter key, rather than needing a pre-existing labeled dataset. Separately, on every frame where a hand is detected, the same normalized landmark vector is passed into the previously trained model (loaded once at the start from `model.pkl` using `pickle`) so that a live prediction can be generated. That prediction is drawn onto the frame inside a black rectangle in the top-left corner using `cv2.putText`, giving instant visual feedback about what letter the model thinks is being signed. The loop continues until the user presses "q", at which point the webcam is released and the window closes.

**How `train_model.py` works:** This script is intentionally kept short and separate from `project.py` so that data collection/prediction and model training are decoupled — a user can collect new examples at any time and retrain without touching the webcam logic. It reads `data.csv` with pandas, treating the first column as the label (the letter) and the remaining 42 columns as the feature vector. It then fits a `KNeighborsClassifier` from scikit-learn with `n_neighbors=7` on this data. KNN was chosen over more complex models (like a neural network) because the feature space is small (42 normalized coordinates), the dataset is expected to be modest in size, and KNN performs very well on this kind of low-dimensional, geometrically meaningful data without requiring any hyperparameter tuning or GPU resources. A neighbor count of 7 was chosen empirically as a balance between smoothing out noisy frames (too low a value overfits to single mislabeled examples) and staying responsive to genuinely distinct hand shapes (too high a value blurs together similar letters). Once trained, the model is serialized with `pickle` into `model.pkl`, which `project.py` loads at startup for inference.

One limitation worth noting is that the system currently only tracks a single hand (`results.multi_hand_landmarks[0]`), so two-handed signs are not supported, and prediction accuracy depends heavily on how much and how consistently training data was collected for each letter. Future improvements could include supporting multiple hands, adding a confidence threshold before displaying a prediction, or experimenting with other classifiers such as a support vector machine or small neural network for comparison against the KNN baseline.
